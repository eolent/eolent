# Contributing to Eolent

Thank you for your interest. Eolent is in an early design phase, so the most useful contributions right now are feedback on the specification and documentation.

## How to contribute

1. Open an issue or a discussion describing the problem or idea before large changes.
2. Keep pull requests small and focused on one topic.
3. For changes to `spec/`, explain the reasoning in the pull request. Significant decisions get an ADR in `docs/adr/`.
4. Make sure all example manifests still validate against `spec/module.schema.json`.

## Conventions

- Documentation is written in Markdown, in plain, neutral English.
- The specification stays language-neutral.
- Do not include secrets, credentials or personal data in issues, commits or pull requests.

## Conduct

Be respectful and constructive. A formal code of conduct will be added before the project accepts regular outside contributions.
